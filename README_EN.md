# UpdateKit · Android Update Check + Announcements SDK

> 🤖 This project was generated by AI.

[中文](README.md) | [English](README_EN.md)

A **client-side** Android SDK to safely check for app updates and fetch announcements. Backend is [OpenHub](https://github.com/wanwu2026/OpenHub)'s `update` / `announce` plugins (or any service implementing the same contract).

- Server **signs** manifests and announcements; client **verifies** — the private key never ships in the app
- Updates use **double validation**: verify manifest signature + compare APK signing-certificate SHA-256 (defeats URL substitution)
- Zero third-party runtime dependencies (Android system APIs + `org.json` only)
- Core verification is plain Java (unit-testable); Chinese content is cross-validated byte-for-byte with Python/OpenSSL

> ⚠️ **Honest note**: an API Key shipped in a client can be extracted by reverse engineering; it identifies requests, it is not a secret. Security comes from **signature verification** — even with a stolen Key, an attacker cannot forge the server's signature. See [contract](docs/API_CONTRACT.md) §6.

---

```
App start
 → UpdateKit fetches /update/check and /announce/list with API Key
 → verify signature with embedded public key (fail → discard)
 → update: after download compare APK cert SHA-256 with manifest.signer_fingerprint
 → only then hand the update/announcement to the host for display
```

## Quick start

### Demo (prebuilt APK)

`UpdateKitDemo-release.apk` in Releases (built by GitHub Actions with a temporary key; key changes every build, uninstall before reinstalling). The demo embeds a demo keypair plus signed manifest/announcement so you can **see verification succeed and fail offline**:

- "Verify demo": Chinese manifest/announcement verify → success (proves canonical bytes match)
- "Tamper": change notes/content → verification fails (proves anti-forgery)

> No Android SDK on this machine (aarch64); APK is built on an x86_64 GitHub runner, with real Java unit tests + `:demo:assembleRelease`.

### Integrate (3 steps)

**1. Dependency**: include `sdk` as a library (`implementation project(':sdk')`) or package an AAR.

**2. Init** (`Application.onCreate`):

```java
UpdateKit.init(new UpdateKit.Config(this)
        .baseUrl("https://your.openhub.example/api/v1")
        .apiKey("ohk_xxx")
        .publicKeyBase64(PUBLIC_KEY_BASE64)); // public key only
```

**3. Check / fetch**:

```java
UpdateInfo info = UpdateKit.get().checkUpdate(currentVersionCode);
if (info != null) new UpdateDialog(this).info(info).show();

List<Notice> notices = UpdateKit.get().fetchNotices();
for (Notice n : notices) new NoticeDialog(this).notice(n).show();
```

**Second check after download** (do this):

```java
String actual = Fingerprint.archiveApp(context, downloadedApkPath);
if (!UpdateVerifier.fingerprintMatches(actual, info.signerFingerprint)) {
    // mismatch → refuse to install
}
```

## Signing (the critical part)

Server and client must produce **identical bytes**. Canonical JSON rules:

1. keys sorted;
2. no spaces: `{"a":1,"b":2}`;
3. non-ASCII escaped as `\uXXXX` (including UTF-16 surrogate pairs, e.g. `😀` → `\ud83d\ude00`).

This replicates Python `json.dumps(obj, sort_keys=True, separators=(",", ":"))` (`ensure_ascii=True`). Java: `core/CanonicalJson.java`; `tools/canonical_java.py` is a strict replica, both cross-checked byte-for-byte against Python native output.

- **Manifest** body = all fields
- **Announcement** body = six fields `{product,title,content,level,force_popup,published_at}`; `id` and `signature` are excluded

Algorithm: `SHA256withRSA` (RSASSA-PKCS1-v1_5 / SHA-256), signature in RFC4648 Base32 (no padding). See [contract](docs/API_CONTRACT.md) §4.
